## 5. Flow "หมดชั่วคราว" กับ "หมด"

| สถานะ | เกิดจาก | ลูกค้าเห็น | สั่งได้ไหม |
| --- | --- | --- | --- |
| พร้อมขาย (`available`) | จำนวนพร้อมขาย > 0 | ปกติ | ได้ |
| หมดชั่วคราว (`slow`) | จำนวนพร้อมขายเหลือ 0 แต่ยังเปิดขาย | "รอนานขึ้น 5–10 นาที" | **ได้** |
| หมด (`closed`) | เชฟ/ผู้จัดการกดปิดขาย (`is_available = 0`) | "หมด" | ไม่ได้ |

- [ ] ตั้งจำนวนเมนู A = 2 แล้วลูกค้าสั่ง 3 → สั่งได้ · ตัดจำนวนเท่าที่มี (`stock_taken` = 2) · ตอบ `slow_items` · เมนู A กลายเป็น "หมดชั่วคราว" แต่ไม่ถูกปิดขาย
- [ ] เมนู A ที่หมดชั่วคราว ลูกค้ายังเห็นและสั่งได้ · ครัวเห็นรายการตามปกติ
- [ ] กดปิดขายเมนู B → ลูกค้าเห็น "หมด" สั่งไม่ได้ · Dashboard การ์ด "เมนูขายไม่ได้" มีเมนู B
- [ ] เปิดขายเมนู B กลับตอนจำนวนเป็น 0 ได้ (ไม่ต้องเติมก่อน)
- [ ] ระบบไม่ปิดขายเองตอนจำนวนเป็น 0
- [ ] ครัวยกเลิกรายการเพราะวัตถุดิบหมด → ปิดเมนูนั้น
- [ ] ยกเลิกออเดอร์ → คืนจำนวนพร้อมขายเท่าที่ตัดไปจริง (BR-07)
- [ ] Dashboard: เมนูที่เหลือ ≤ 1 ล็อตหรือหมดชั่วคราวอยู่ในการ์ด "เมนูใกล้หมด" · เมนูที่ปิดขายอยู่ใน "เมนูขายไม่ได้"

## 6. กติกาห้อง VIP

**มาสาย**
- [ ] กด "มาถึง" ได้ตลอดช่วงจอง ไม่จำกัดว่ามาสายกี่นาที (FR-36)
- [ ] การจองที่ยืนยันแล้ว เลยเวลาเริ่ม ≥ 10 นาทียังไม่มา → Dashboard ขึ้นป้าย **"โทรตาม"** พร้อมเบอร์ลูกค้า กดโทรได้
- [ ] กด "ไม่มา" ได้หลังจบช่วงจองเท่านั้น · มัดจำไม่คืน (FR-37 · BR-16)

**ปล่อยห้อง**
- [ ] ลูกค้ายืนยันไม่มา → กดปล่อยห้อง → สถานะ `released` · มัดจำไม่คืน (FR-37)
- [ ] เวลาที่เหลือของห้องกลับเป็นว่าง จองช่วงนั้นใหม่ได้ · Gantt บน Dashboard แท่งสิ้นสุดที่เวลาปล่อยห้อง

**เลื่อน**
- [ ] ลูกค้าเลื่อนได้ 1 ครั้ง · ไม่เกินวันเดิม + 14 วัน · ต้องแจ้งก่อนวันจองเดิม ≥ 1 วัน · ห้องต้องว่าง · มัดจำย้ายตาม (FR-35)
- [ ] เลื่อนครั้งที่ 2 / เกิน 14 วัน / แจ้งวันเดียวกัน → ระบบไม่ให้เลื่อน พร้อมข้อความบอกเหตุผล
- [ ] เปลี่ยนแพ็กเกจตอนเลื่อนได้ (ส่วนต่างคิดตามแพ็กเกจใหม่)
- [ ] ร้านเลื่อนให้ (เหตุสุดวิสัย) ไม่นับสิทธิ์เลื่อน ไม่จำกัด 14 วัน บันทึกเหตุผล (FR-37)

**ยกเลิก / คืนมัดจำ**
- [ ] ลูกค้ายกเลิก (refund 0) → มัดจำไม่คืน · Dashboard นับเป็น "มัดจำที่ยึด" ของวันที่กดยกเลิก
- [ ] ร้านยกเลิกเพราะเหตุสุดวิสัย (refund 1 · ผู้จัดการขึ้นไป) → คืนมัดจำ บันทึกคนคืนและเวลา · Dashboard **ไม่นับ** ในยอดขาย
- [ ] เหมาวัน: กดมาถึงได้รอบละครั้ง (บิลกะเช้า / บิลกะเย็น) · ค่าห้องและมัดจำคิดที่บิลกะเช้าครั้งเดียว

## 8. สาธิต Microservices (วัน demo ใช้ `npm run start:all`)

- [ ] **ปิด kitchen-service** (หน้าสถานะระบบ → ปิด service ครัว หรือ Ctrl+C ที่ `npm run dev:kitchen`)
  - [ ] ลูกค้ายังสแกน QR และสั่งอาหารได้ · หน้าอื่นของร้านใช้ได้ปกติ
  - [ ] จอครัวขึ้น "ระบบครัวขัดข้องชั่วคราว" (503) เฉพาะจอครัว
  - [ ] เปิดกลับ → จอครัวเห็นออเดอร์ที่สั่งระหว่างดับครบทุกรายการ
- [ ] **ปิด notify-service**
  - [ ] ลูกค้าขอ OTP สมัครสมาชิกได้ (OTP แสดงบนจอเหมือนเดิม) · หน้าสถานะระบบเห็นงานค้างในคิว `notify` (pending)
  - [ ] เปิดกลับ → งานในคิวถูกส่งครบ ประวัติข้อความ (`/api/notifications`) มีครบ · ไม่มีงาน failed
- [ ] **ปิด inventory-service**
  - [ ] Dashboard ยังเปิดได้ · การ์ด "วัตถุดิบต่ำกว่าจุดสั่งซื้อ" และ "ใบแจ้งหนี้รอจ่าย" ขึ้น **"ระบบคลังสินค้าไม่พร้อมใช้"** · การ์ดอื่น (ยอดขาย โต๊ะ VIP เมนู) แสดงปกติ · แถบเหลืองวัตถุดิบต่ำหายไป
  - [ ] หน้าวัตถุดิบ / ใบสั่งซื้อ / รับของขึ้น 503 เฉพาะหน้านั้น
  - [ ] เปิดกลับ → Dashboard แสดงข้อมูลคลังเองภายใน 10 วินาที ไม่ต้องรีเฟรช
- [ ] **`npm run start:all` เปิด service ที่ดับกลับเอง**: กด "ปิด service (สาธิต)" ในหน้าสถานะระบบ (เจ้าของ) → service กลับมาเองภายในประมาณ 3 วินาที · หน้าสถานะระบบขึ้น "ทำงาน" อีกครั้ง
