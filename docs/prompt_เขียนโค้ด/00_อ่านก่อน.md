## Microservices (เฟส 2 เป็นต้นไป)

ระบบแยกเป็น 4 ตัว ทำงานอิสระ ตัวหนึ่งดับ ตัวอื่นยังใช้ได้

| ระบบ | port | API | เจ้าของงาน |
| --- | --- | --- | --- |
| ระบบหลัก (Gateway) | 3000 | หน้าเว็บทั้งหมด + API อื่นทั้งหมด | ทุกคน (`routes/`) |
| kitchen-service | 4001 | `/api/kitchen` | คน 7 |
| inventory-service | 4002 | `/api/ingredients` `suppliers` `purchase_orders` `goods_receipts` `stock` | คน 1, 2, 5, 6, 4 (เฟส 4) |
| notify-service | 4003 | `/api/notifications` + หยิบงานจากคิว `notify` (จำลอง ไม่ส่งจริง) | คน 2 (เฟส 3) |

- **เปิดทั้งหมด:** `npm run dev:all` (แก้ไฟล์แล้วรีสตาร์ทเอง) · วัน demo ใช้ `npm run start:all` (service ดับแล้วเปิดกลับเองใน 3 วินาที)
  ตั้ง DB_PORT เหมือนเดิม เช่น cmd: `set "DB_PORT=3307" && npm run dev:all`
- **เปิดเฉพาะ service ของตัวเอง:** `npm run dev:kitchen` / `dev:inventory` / `dev:notify` (ต้องเปิด `npm run dev` ด้วย)
- **API ของ service** เขียนที่ `services/<service>/routes/<api>.js` · require lib ด้วย `'../../../lib/...'`
- **หน้าเว็บไม่ต้องรู้ port** เรียก `api.get('kitchen')` เหมือนเดิม Gateway ส่งต่อให้ · service ดับ = API ตอบ 503 "ระบบ...ขัดข้องชั่วคราว"
- **คุยข้าม service:** `callService(req, 'inventory', '/api/...')` หรือส่งงานเข้าคิว `publish('notify', {...})` ห้ามอ่านตารางของ service อื่นตรง
- **ตารางใหม่ 3 ตาราง** (sessions, event_queue, notifications) server สร้างให้เองตอนเปิด ไม่ต้อง import
- **หน้าสถานะระบบ** `/admin/system.html` (ผู้จัดการ/เจ้าของ) ดู service เขียว/แดง, คิวงาน, ปุ่มปิด service เพื่อสาธิต
